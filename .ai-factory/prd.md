# SaveStreak (save-streak)

# PRD
## Background / Problem
- 습관 개선 앱은 많지만, **절약되는 돈을 “자산 목표(예: 아이폰/여행경비)”와 직접 연결해 동기부여**하는 형태는 드물다.  
- 본 아이디어는 “하루 담배 1갑 = 월 135,000원 = 1년 162만원 = 5년 후 노트북 3대”처럼 **절약액을 기간/목표 구매력으로 환산**해 체감 가치를 키우는 것이 핵심이다.
- 문제는 사용자가 ‘참았다’라는 행동을 매일 반복하기 어렵고(알림/푸시 제한), 스트릭이 끊기면 이탈이 급증한다는 점이다. 따라서 **간단한 체크인 + 즉시 보상(누적 금액/목표 D-day/배지)**로 반복 동기를 만들어야 한다.

## Goal (1-sentence product definition)
사용자가 선택한 나쁜 습관을 **매일 체크인**하여 절약액을 누적하고 **목표 자산까지 남은 D-day를 확인**하도록 만들어, 출시 4주 내 **7일 스트릭 달성률 20%**를 달성한다.

## Non-goals
- 푸시 알림/시스템 알림(웹뷰 한계) 및 OS 연동 리마인더
- 서버 기반 계정/동기화, 다기기 데이터 이전
- SNS 공유/커뮤니티/랭킹(핵심 기능 아님)
- 의료적 상담, 금연/금주 치료 가이드 제공(의료 서비스 아님)
- 복잡한 3rd-party 건강/결제/트래킹 SDK 연동

## Target Users (personas + use cases)
1) **김민수 (29, 직장인)** — 커피·배달 지출이 새는 걸 알지만 기록/관리 앱은 귀찮음  
- 사용 케이스: “하루 3,000원만 아껴도 한 달 얼마지?” → 체크인으로 누적, 목표(예: 에어팟) D-day 확인

2) **이서연 (33, 직장인)** — 금연/절주를 시도하지만 스트릭이 끊기면 금방 포기  
- 사용 케이스: “오늘 하루 참았다를 버튼 한 번으로 끝내고 성취감을 보고 싶다” → 스트릭/배지로 유지

## Target Market
- South Korea, 토스 사용자 기반(20–40대 중심, 금융 관심 높고 모바일 네이티브).
- 포지셔닝: **건강 앱이 아니라 ‘금융 동기부여형 절약 습관 트래커’**.

## Data Entities (nouns with key fields)
> 저장소: localStorage (약 5MB 내), 서버 없음

- **Habit**
  - `id` (string)
  - `category` (enum: smoking | coffee | delivery | alcohol | impulse | etc)
  - `title` (string; 기본은 카테고리명)
  - `unitPriceKRW` (number; “하루 참으면 절약되는 금액”)
  - `createdAt` (ISO string)
  - `isActive` (boolean)

- **CheckIn**
  - `id` (string)
  - `habitId` (string)
  - `date` (string; `YYYY-MM-DD`, KST 기준)
  - `savedAmountKRW` (number; 보통 `unitPriceKRW`)
  - `createdAt` (ISO string)

- **Goal**
  - `id` (string)
  - `title` (string; 예: 아이폰, 여행 경비)
  - `targetAmountKRW` (number)
  - `createdAt` (ISO string)
  - `isActive` (boolean)

- **Badge**
  - `id` (string; 예: `streak_7`)
  - `title` (string)
  - `unlockedAt` (ISO string | null)

- **AppSettings**
  - `weekStartsOn` (enum: mon | sun)
  - `lastOpenedDate` (string; `YYYY-MM-DD`)
  - `promotionRewardGranted` (boolean; 첫 사용 보상 지급 여부 등)

## Core Flow (numbered steps)
1. 토스 앱에서 미니앱 진입  
2. 홈에서 “습관 추가” → 카테고리(담배/커피/배달/음주/충동구매 등) 선택 → **하루 절약 금액(단가)** 입력 → 저장  
3. 홈에서 오늘의 습관 카드(또는 리스트)에서 **“오늘 참았어요”** 탭 → 해당 날짜 체크인 생성 → **누적 절약액 + 스트릭** 즉시 갱신  
4. 홈 상단/목표 영역에서 **목표 자산(금액) 설정** → 현재 누적 절약액 기준 **목표 달성까지 D-day** 확인  
5. “주간 리포트” 진입 → **리워드 광고 시청(TossRewardAd)** → 카테고리별 주간 절약 합계/추이 공개  
6. 스트릭이 7일에 도달하면 “배지 잠금 해제” 화면 → **리워드 광고 시청(TossRewardAd)** → **특별 배지** 언락 및 보관함에서 확인

## Success Metrics (measurable)
- **DAU 500+** (출시 4주 내)
- **체크인 완료율(홈 진입 대비 1회 이상 체크인)**: 60%+
- **7일 스트릭 달성률**: 20%+
- **주간 리포트 리워드 광고 시청 완료율(리포트 진입 대비)**: 35%+
- **D7 Retention**: 15%+

## MVP Scope (exhaustive feature list)
1) **습관 생성/관리(로컬)**
- 카테고리 선택 + 하루 절약 금액 입력 + 활성/비활성(숨김) 처리
- 여러 습관 동시 관리(리스트)

2) **매일 체크인 + 스트릭 계산**
- “오늘 참았어요” 버튼으로 날짜별 체크인 1회 생성(습관별 1일 1회)
- 연속 체크인(스트릭) 계산 및 표시

3) **누적 절약액 집계**
- 전체 누적 절약액, 습관별 누적 절약액 계산/표시

4) **목표 자산 연결 + D-day 카운터**
- 목표(이름/목표금액) 설정
- 현재 누적 절약액으로 목표까지 남은 금액/예상 남은 일수(D-day) 표시

5) **주간 절약 리포트(리워드 광고 게이트)**
- 주간 합계/카테고리별 합계/간단한 추이(텍스트/바 형태)
- 리포트 상세는 TossRewardAd 시청 후 노출

6) **7일 스트릭 배지 잠금 해제(리워드 광고 게이트)**
- 스트릭 7일 달성 조건 충족 시 배지 해제 CTA 노출
- TossRewardAd 시청 후 배지 unlock 및 배지 목록에서 확인

+ 광고 배치(템플릿 컴포넌트 사용)
- 홈 누적 금액 카드 하단 **배너 광고(AdSlot)** 1개

## Monetization Strategy
- **인앱 광고**(권장): 무료 유틸/동기부여 앱에 적합  
  - 홈: 배너 광고(AdSlot) 1개  
  - “결과/분석/보상” 순간에만 리워드 광고(TossRewardAd) 게이트:
    - 주간 리포트 상세
    - 7일 스트릭 배지 잠금 해제
- 수익 예측 시(정책): **순수익 = 총수익 × 0.85** (2026.04.01부터 수수료 15%)

## Assumptions
1. 사용자는 하루에 1회 이상 토스에 접속할 가능성이 높아, 푸시 없이도 홈 진입이 발생한다.  
2. “오늘 참았어요” 체크인은 **습관별 1일 1회**로 제한하는 것이 혼란을 줄인다.  
3. localStorage 용량(~5MB) 내에서 체크인 데이터는 충분히 저장 가능하다(텍스트 기반).  
4. 목표 D-day는 “미래 예측”이 아니라 **현재 누적 기반의 단순 환산(남은 금액/일수)**으로도 동기부여가 된다.  
5. 리워드 광고는 “결과/보상 화면”에서만 게이트할 때 이탈이 가장 적다.  
6. 건강/의학 정보 제공이 아니라 **절약/자산 목표** 중심이면 정책/포지셔닝 리스크가 낮다.  
7. 스트릭이 끊기는 문제는 MVP에서 ‘최소한의 재동기부여 UI’(예: 다시 시작 CTA)로 완화 가능하다.  
8. 토스 미니앱 구현은 프로젝트 표준( **Vite + React + TypeScript + TDS + React Router** )을 따른다.
